# Monk Learning API — Drona AI Tutor Backend

Monk Learning API is the core Python (FastAPI) backend service for **Drona**, a voice-first, interactive AI tutor built for Indian high school students (Class 11–12, preparing for JEE, NEET, and CBSE Board exams).

Drona delivers structured 30-minute spoken lessons supported by a live, dynamic whiteboard, real-time option chips (Ask Sheet), state-machine pacing, and automated misconception diagnostics.

## 1.5 Directory & Folder Breakdown

Here is an explanatory guide to every primary directory in the backend repository and what it does:

```text
monk-learning-api/
 ├── app/                      # Main FastAPI application source code
 │    ├── routers/             # API HTTP route controllers (practice questions, Drona sessions)
 │    ├── drona/               # Core Drona AI Tutor engine modules
 │    │    ├── planner.py      # Authors 6–9 segment lesson plans using DeepSeek V4 Pro
 │    │    ├── tutor.py        # Spoken turn streaming engine & board item assignment
 │    │    ├── state.py        # Session state machine (phase, segment, attempts counter)
 │    │    ├── voice_proxy.py  # Sarvam STT & Rumik Silk TTS WebSocket connection pool
 │    │    ├── live_session_ws.py # Live WebSocket endpoint streaming PCM audio & board events
 │    │    └── scoping.py      # Out-of-topic safety tier classification
 │    ├── auth.py              # Supabase JWT authentication middleware & user verification
 │    ├── config.py            # Environment settings (API keys, models, DB connections)
 │    ├── db.py                # Supabase PostgreSQL client initialization
 │    └── main.py              # FastAPI app initialization, CORS, & platform metrics sampler
 ├── .agents/                  # Agentic standing rules (AGENTS.md repository root instructions)
 ├── prompts/                  # System prompts driving LLM behaviors (planner.md, tutor.md, scoping.md)
 ├── migrations/               # PostgreSQL SQL schema DDL migrations (0001 to 0011 SQL scripts)
 ├── scripts/                  # Official CLI diagnostic & maintenance tools (session_log.py, etc.)
 ├── scratch/                  # Temporary data files, trial scripts, and local audit utilities
 └── tests/                    # Automated Pytest suite for API endpoints and guardrails
```

### Folder Explanations

- **`app/`**: Contains all Python application code executed by Uvicorn / Gunicorn in production.
  - **`app/routers/`**: Handles incoming HTTP REST requests (e.g., `/drona/session/start`, `/practice`).
  - **`app/drona/`**: The core intelligence hub of Drona. Manages the LLM prompt construction, JSON parsing, TTS voice connection pool, and real-time WebSocket protocol.
- **`prompts/`**: Houses markdown prompt templates (`planner.md`, `tutor.md`, `scoping.md`). Changing these files immediately alters Drona's spoken persona, whiteboard rules, or plan structures.
- **`migrations/`**: Raw SQL migration files executed on Supabase PostgreSQL. Contains DDL statements for RLS policies, `lesson_plans`, `drona_sessions`, `drona_turns`, `drona_platform_metrics`, and `drona_wellbeing_flags`.
- **`scripts/`**: Verified CLI utilities for developers (e.g., `scripts/session_log.py` for dumping live turn execution traces from DB, `scripts/drive_full_9_segments.py` for driving 9-segment test sessions).
- **`scratch/`**: Workspace scratchpad for temporary data dumps, standalone test runners, and one-off database inspection scripts. Not deployed to production.
- **`tests/`**: Unit and integration test suites validating API contracts, RLS policies, and prompt guardrails.

## 1. Architecture & Session Lifecycle

Drona structures learning hierarchically into subtopics, segments, and turns:

```text
SESSION (One Subtopic, ~25–35 minutes)
 └── SEGMENT × 6–9   (~3–4 minutes per segment, generated by Drona Planner)
      └── TURN × 2–4  (Drona teaches & writes board events; student responds)
```

### Core Execution Flow
1. **Planner Phase**: `app/drona/planner.py` invokes `deepseek-v4-pro` to author a 6 to 9 segment plan grounded in vector retrieval chunks.
2. **Tutor Turn Stream**: `app/drona/tutor.py` processes student utterances using `deepseek-v4-flash`, computing exact per-turn board item slices and state transitions.
3. **Voice Proxy Pipeline**: `app/drona/voice_proxy.py` manages audio STT (Sarvam) and sentence-by-sentence TTS synthesis (Rumik Silk WS API) using a per-turn connection leasing pool.
4. **WebSocket Handler**: `app/drona/live_session_ws.py` streams binary PCM audio, board events, state frames, and Ask Sheet chips to the Next.js frontend over a single WebSocket connection.

## 2. Model Matrix & LLM Guardrails

Per **AGENTS.md Standing Rule 5**, all LLM invocations use explicitly configured model strings and disabled reasoning bodies to prevent token budget exhaustion:

| Service Component | Model String | Thinking Mode | Temperature | Purpose |
|---|---|---|---|---|
| **Lesson Planner** | `deepseek-v4-pro` | `disabled` | `0.0` | Authors 6–9 segment lesson plan with rubrics and board content. |
| **Tutor Engine** | `deepseek-v4-flash` | `disabled` | `0.0` | Generates turn speech, board events, and phase requests. |
| **Scoping Engine** | `deepseek-v4-flash` | `disabled` | `0.0` | Out-of-topic detection and safety tier classification. |
| **Audio Transcription** | `gpt-4o-mini` / Sarvam | — | `0.0` | Transcribes student audio and fallbacks. |

> **Critical Guardrail**: DeepSeek V4-Flash defaults to chain-of-thought unless explicitly disabled via `extra_body={"thinking": {"type": "disabled"}}`. Startup model assertions enforce strict string matching.

## 3. Comprehensive History of Issues & Solutions

### 3.1 Turn-1 Premature Questions & Prompt-Only Failure
- **The Problem**: New sessions frequently opened with Drona asking a question immediately on Turn 1 of Segment 1 (e.g. *"Ab batao, kis type ki force ki potential energy ho sakti hai?"*) before explaining any theory or emitting board events.
- **Root Cause**: Relying solely on the LLM prompt (`tutor.md`) to decide `phase_request`. When the model returned `phase_request: "awaiting_answer"` on Turn 1, the backend allowed it. Additionally, legacy cached plans stored `board_content` as a string, evaluating assigned items to `[]`.
- **The Solution**: 
  1. **Backend Hard Override**: In `app/drona/tutor.py`, when `turn_within_segment == 1`, the backend hard-overrides `parsed_json["phase_request"] = "teaching"`, `parsed_json["question_type"] = None`, and `parsed_json["check_options"] = []` regardless of LLM output.
  2. **Prompt Instruction**: Added explicit prompt rule: *"Turn 1 MUST Teach Only (NO QUESTIONS ON TURN 1)"*.

### 3.2 Board Content Density Floor & Turn-1 Dumps
- **The Problem**: In initial segments, the tutor either dumped all authored board items in Turn 1 (leaving Turns 2 and 3 with zero board events) or hallucinated concepts from future segments when running out of material.
- **Root Cause**: The prompt enforced a fixed floor of "4–6 board events per turn", which logically contradicted authored lesson plans that contained only 4 board items for the entire segment.
- **The Solution**:
  1. **Planner Floor**: Updated `planner.md` and added validation in `planner.py` requiring **6 to 9 board items per segment** (targeting ~60 total across a 30-minute session).
  2. **Backend Slice Assignment**: `tutor.py` calculates `turn_within_segment` and mathematically assigns `ceil(N/3)` board items to each turn (Turn 1 gets items 1 to $N/3$, Turn 2 gets $N/3+1$ to $2N/3$, Turn 3 gets the remainder).
  3. **Auto-Fallback**: If the tutor emits 0 board events while items are assigned, the backend auto-populates `board_events` from the assignment and flags a `zero_board_events` / `fallback_board_events` violation in telemetry.

### 3.3 "Samajh Aaya?" Check-in Box Taxonomy & Ask Sheet Stalls
- **The Problem**: Drona would end spoken speech with check-in phrases like *"samajh aaya?"* or *"clear hai?"*, but the Ask Sheet would fail to mount, leaving the UI stuck on `"Connecting..."` or `"Listening"`.
- **Root Cause**: A previous prompt rule classified *"samajh aaya?"* as a "rhetorical check-in" returning `phase_request: "teaching"`. As a result, Drona spoke a question aloud, but the backend returned `phase_request: "teaching"`, so no Ask Sheet mounted and Drona paused speech waiting for an answer that the UI had no input mechanism for.
- **The Solution**:
  Rebuilt the question classification taxonomy into four explicit kinds:

| Kind | Example Speech | `phase_request` | `question_type` | Options Emitted |
|---|---|---|---|---|
| **Understanding Check-in** | *"samajh aaya?"*, *"clear hai?"*, *"theek hai na?"* | `awaiting_answer` | `understanding` | `["Haan, samajh aaya", "Thoda dubara samjhao"]` (2 chips) |
| **Procedural** | *"aage badhein?"*, *"next topic pe chalein?"* | `awaiting_answer` | `procedural` | `["Haan, aage badho", "Ek baar dubara samjhao"]` (2 chips) |
| **Content Question** | Recall, application, or numerical choice | `awaiting_answer` | `check` / `checkpoint` | 3 plausible option chips |
| **Pure Transition** | *"Chalo aage badhte hain"*, *"Ab dekhte hain..."* (No `?`) | `teaching` | `null` | None |

- **Strict Enforcement Rule**: **Only a statement with no question mark gets `teaching`.** If spoken `speech` ends in `?`, the backend forces `phase_request: "awaiting_answer"` and auto-populates options if empty.
- **State Machine Handling**: `understanding` check-ins set `grade: null` (never logged as misconceptions). Tapping *"Thoda dubara samjhao"* triggers a re-explanation without advancing the segment or incrementing question attempt counters.

### 3.4 Database Cache Contamination & Schema Drift
- **The Problem**: Features worked in local tests but failed in production.
- **Root Cause**: The production Supabase database contained 34 cached `lesson_plans` generated weeks earlier where `board_content` was stored as a newline-separated `string` (instead of a list of objects) and segments had only 4 items. On cache hit, `get_or_create_plan` loaded these outdated plans, bypassing all local prompt improvements.
- **The Solution**:
  1. Executed a database purge removing all 34 string-shape plans from Supabase.
  2. Implemented **load-time plan schema validation** inside `get_or_create_plan()` in `app/drona/planner.py`. Every cached plan loaded from DB is validated with `validate_plan_json()`. If it fails validation (string shape, <6 items, invalid misconceptions), it is automatically purged from DB and regenerated on the fly.

### 3.5 Railway Telemetry Noise & Vercel TypeScript Build Breaks
- **The Problem**: Railway production logs were drowned in HTTP 200 logs and 30-second sampler lines. Concurrently, Vercel frontend builds failed due to property name mismatches (`isRecording` vs `isListening`).
- **The Solution**:
  1. **Noise Silencing**: Set log levels for `httpx`, `postgrest`, `supabase`, and `uvicorn.access` to `WARNING`. Reduced platform metrics sampler logging to a 10-minute aggregate summary. Silenced boot prewarm logs to a single `INFO` line: `✅ [FILLER PREWARM] 4 voices cached in 34.2s`.
  2. **Session-Scoped Trace Log**: Every session line in logs is prefixed with `[s:<session_id[:8]>]` detailing turn execution, assigned vs emitted board items, LLM token stats, and TTS duration.
  3. **One-Command Debugger**: Created `scripts/session_log.py <session_id>` to reconstruct and dump complete, readable session execution traces directly from `drona_turns` DB table.
  4. **TypeScript Fix**: Resolved `VoiceClientState` type property mismatch in `SessionView.tsx` and verified local `npm run build` prior to Vercel deployment.

## 4. Known Limitations & Active Technical Debt

1. **Sarvam WebSocket STT API Key Restriction**:
   - Sarvam WebSocket STT returns `HTTP 403 Forbidden` on the current account key. The system operates on a robust REST STT audio buffer pipeline fallback (`SaarasSTTProxy`).
2. **Rumik Connection Pool Idle Timeout (60s Limit)**:
   - Rumik Silk WebSockets time out after 60s of idle time. Ping frames do NOT reset the idle timer. Connection leases are dynamically acquired per turn and released 4s after sentence delivery.
3. **Multi-Turn Check-in Re-explanation Arc**:
   - When a student requests *"Thoda dubara samjhao"*, the prompt re-explains the sub-concept. If history context is truncated, the LLM can occasionally repeat analogies.
4. **LaTeX Rendering Delimiters**:
   - Math equations in `board_events` require double backslash escaping `\\frac{a}{b}` in JSON. Single backslashes break JSON decoding and require fallback repair parsing.

## 6. Database Schema & Security (RLS)

All database access adheres to **AGENTS.md Rule 9**:

- **Row Level Security (RLS)** is enabled across all tables.
- Student tables (`drona_sessions`, `drona_turns`, `student_misconceptions`) use owner-read policies (`auth.uid() = user_id`). FastAPI writes directly using the service role key.
- Content and rubric tables (`questions`, `pdf_chunks`, `lesson_plans`) have **RLS ENABLED with ZERO policies**, preventing any direct client-side read or modification of model answers or rubrics.
- Sensitive fields (`model_answer`, `rubric`, `expected_misconceptions`, `grade`, `mistake_tag`) are consumed server-side and **never sent to the client**.
